= OCI NSSシステムの構成分析
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factoryは、OCI NSSシステムの構成を定期的に分析し、構成上の問題がないかどうかを判断します。問題が検出された場合、Workload Factoryは問題点を示し、ストレージ環境が最高のパフォーマンス、コスト効率、およびベストプラクティスへの準拠を実現できるよう、変更すべき点を説明します。

主な機能は次のとおりです：

* 日次構成分析
* 自動ベストプラクティス検証
* プロアクティブな可観測性
* 洞察から行動へ
* OCI Well-Architected Framework アドバイザー




[[how-it-works]]
== 仕組み

Workload Factoryは、サポートされているクラウドストレージ環境におけるワークロードを毎日分析します。この分析により、優れたアーキテクチャのステータス、インサイト、および推奨事項が提供されます。

日々の分析が完了すると、デプロイメントのWell-architectedダッシュボードに、構成が「最適化済み」または「最適化されていない」として表示されます。設定に関する問題はカテゴリ別に整理されており、推奨事項も併せて掲載されています。Workload Factoryは、推奨される変更を実施するための詳細な手順を提供します。

お客様の環境に適用されない構成の分析を無視することができます。これにより、不要なアラートや不正確な最適化結果を回避できます。



[[why-it-matters]]
== 重要な理由

Workload Factory は、継続的な評価と推奨事項、および修復策を組み合わせることで、大規模なストレージ、データベース、および VMware 環境にベストプラクティスを適用します。自動化された修正機能は、人的ミスを減らし、均一な管理を確保し、ワークロードインフラストラクチャ全体でパフォーマンスと信頼性を維持します。

[[best-practices-and-recommendations-for-storage-workloads]]
== ストレージワークロードに関するベストプラクティスと推奨事項

適切に設計されたダッシュボードは、ストレージ構成をONTAPのベストプラクティスおよびAWS Well-Architected Frameworkに照らして評価します。この評価では、改善点や修正点も推奨します。

適切に設計された分析では、構成をフレームワークの次の柱に分類します：_信頼性_、_セキュリティ_、_運用効率_、_コスト最適化_、および_パフォーマンス効率_。


NOTE: 現在、NetApp Workload Factoryはすべての構成に対してワークロード固有の推奨事項を提供していません。ワークロードのニーズに合わせて設定を調整してください。



[[reliability]]
=== 信頼性

信頼性とは、障害が発生した場合でも、ワークロードが意図された機能を正確かつ一貫して実行することを保証するものです。

* ファイルオブジェクト容量
+
ボリューム容量制限に達しないように、ファイル容量のしきい値を引き上げるべきです。ファイル容量（iノード）が不足しているため、ボリュームへの追加データの書き込みができません。Workload Factoryは、新規ファイルの作成を可能にするため、ファイル容量の使用率を80%未満に維持することを推奨しています。

* *Snapshotポリシー*
+
効率的なバックアップと迅速なリストアのために、ローカルSnapshotをスケジュール設定してください。Snapshotは、ボリュームのポイントインタイムイメージを瞬時に作成します。この推奨事項はデータベース環境には適用されません。

* *SSDキャパシティのヘッドルーム*
+
SSDストレージ層の容量は、使用率が80%を超えないようにしてください。これは、キャパシティプールストレージ層へのデータの読み書きに影響を与え、ファイルシステムのスループット容量にも影響を与える可能性があります。容量が不足すると、データボリュームは読み取り専用になります。新しいデータを書き込もうとするサービスも失敗します。





[[operational-excellence]]
=== 運用の卓越性

運用上の卓越性により、ワークロードが効果的に運用および監視され、ユーザーの要件をサポートできることが保証されます。

* *ホストから見える容量レポート*
+
ホストから見える容量レポートを有効にすることで、ボリュームレベルでのストレージ使用状況をより詳細に把握できます。

* *ボリューム容量のヘッドルーム*
+
データの増加に対応し、予期しない容量の問題を防ぐために、ボリューム容量のヘッドルームは10%に設定する必要があります。





[[cost-optimization]]
=== コスト最適化

コストの最適化により、コストを低く抑えながらビジネスの価値を最大限に高めることができます。

* *コールドデータ階層化* スナップショットのみの階層化ポリシーを使用します。このポリシーでは、アクティブなデータはSSD階層に保持され、スナップショットデータのみが容量階層に移動します。このアプローチにより、ストレージコストを削減しながら、データベースワークロードの低レイテンシのパフォーマンスを維持できます。7日間のクーリング期間のあとにスナップショットデータを階層化します。
* *スナップショットのクリーンアップ*
+
不要になった古いスナップショットや手動で作成したスナップショットは削除してください。削除することでコストを削減し、整理整頓に役立ちます。特に、SLAや復旧ニーズに必要でない場合はなおさらです。

* *ストレージ効率*
+
ストレージ効率化機能（コンパクション、圧縮、重複排除）を有効にすることで、ストレージ利用率を最適化し、SSDティアのコストを削減します。
