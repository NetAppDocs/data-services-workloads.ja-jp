= NetApp Workload Factory for Databasesを使用してMicrosoft SQL Serverワークロードを保護します
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Workload FactoryコンソールからNetApp Backup and Recoveryを使用して、Microsoft SQL Serverアプリケーションデータを保護します。この統合により、以下の保護目標を達成できます：ローカルのプライマリAmazon FSx for NetApp ONTAP（FSx for ONTAP）ストレージ上のローカルスナップショットでワークロードをバックアップし、セカンダリFSx for ONTAPストレージにワークロードをレプリケートします。



[[about-this-task]]
== タスク概要

Workload Factoryは、リソースの検出、前提条件の検証、およびMicrosoft SQL Server向けプラグインの設定とインストールを自動化し、NetApp Backup and Recoveryを使用したワークロードの保護に備えます。このプラグインは、Microsoft SQL Serverワークロードの保護を可能にするNetAppソフトウェアのホスト側コンポーネントです。

NetApp Backup and Recoveryは、NetApp SnapMirrorデータレプリケーション技術を活用してスナップショットコピーを作成し、バックアップ場所に転送することで、すべてのバックアップが完全に同期されるようにします。

Backup and Recoveryでの保護の詳細については、link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["Backup and Recoveryを使用したMicrosoft SQLワークロードの保護の概要"^]を参照してください。



[[before-you-begin]]
== 開始する前に

Backup and Recoveryを使用してMicrosoft SQL Serverワークロードを保護するには、以下の要件を満たす必要があります。

* 環境がlink:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#microsoft-sql-server-workload-requirements["Backup and RecoveryのSQL Server要件"^]を満たしていることを確認してください。
* link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#in-netapp-console["NetApp Consoleの要件を完了する"^]設定、IAMロールの割り当て、コンソールエージェントのインストールなどを含みます。


NetAppアカウントへの組織管理者アクセス権がある場合、 `backup and recovery super admin`ロールは、<<NetApp Backup and Recoveryを使用した保護の準備,NetApp Backup and Recoveryを使用した保護の準備>>したときに自動的に割り当てられます。

* コネクタでホストの名前解決を設定します
+
データベースを検出するには、Connectorでホスト解決を設定する必要があります。ホストデバイスで、 `/etc/hosts`ファイルにIPアドレスとホスト名のマッピングを追加します。

+
** link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-licensing.html["NetApp Backup and Recoveryのライセンスを設定する"^]






[[prepare-for-protection-with-netapp-backup-and-recovery]]
== NetApp Backup and Recoveryを使用した保護の準備

NetApp Backup and Recoveryを使用してMicrosoft SQL Serverリソースを保護するための準備プロセスを完了します。

.手順
. link:https://console.netapp.com["NetApp Console"^]にログインします。
. メニュー image:workloads-menu-icon.png["ハンバーガーメニューアイコンは、Workload Factoryのメニュー項目であるWorkloadsに移動するために使用します"] から、*ワークロード* > *データベース* を選択します。
. データベースメニューから、*インベントリ*を選択します。
. インベントリで、エンジンタイプとして*Microsoft SQL Server*を選択します。
. 保護するインスタンスを見つけて、メニューから *保護* を選択します。
. 指示された場合は、管理者権限を持つWindowsの認証情報を入力してください。
+
保護のためにNetApp Backup and Recoveryを使用するには、SQL ServerインスタンスをWindows認証情報を使用してWorkload Factoryに登録する必要があります。

. 複数のコンソールエージェントがアクティブで利用可能な場合は、ワークロードを登録および保護する*コンソールエージェント*を選択してください。
. データ保護の準備として、Workload FactoryはSQL ServerリソースをBackup and Recoveryに自動的に登録し、Plug-in for Microsoft SQL Serverを構成およびインストールして、SQL Serverインスタンスを保護するための前提条件を満たすリソースを検出します。プロセスを開始するには、*Start*を選択します。
. 前提条件を満たしたら、*Redirect*を選択してBackup and Recoveryにアクセスしてください。


.次の手順
バックアップとリカバリから、Microsoft SQL Serverインスタンスとデータベースを保護するポリシーを作成します。

link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-policies-create.html["Microsoft SQL Serverインスタンスとデータベースを保護するポリシーを作成する方法について説明します。"^]。

関連情報については、Microsoft SQL Serverワークロードを管理するためのlink:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["バックアップとリカバリに関するドキュメント"^]を参照してください。



[[edit-protection-for-microsoft-sql-server-resources]]
== Microsoft SQL Serverリソースの保護を編集

NetApp Backup and Recoveryで既に保護されているMicrosoft SQL Serverインスタンスおよびデータベースの保護を編集できます。保護を編集することで、保護対象のSQL Serverインスタンスの保護ポリシーやスケジュールを変更できます。

.手順
. link:https://console.netapp.com["NetApp Console"^]にログインします。
. メニュー image:workloads-menu-icon.png["ハンバーガーメニューアイコンは、Workload Factoryのメニュー項目であるWorkloadsに移動するために使用します"] から、*ワークロード* > *データベース* を選択します。
. データベースメニューから、*インベントリ*を選択します。
. インベントリで、エンジンタイプとして*Microsoft SQL Server*を選択します。
. *データベース*タブを選択します。
. 保護を編集するデータベースを見つけてから、メニューから *保護の編集* を選択します。
+
NetApp Consoleのバックアップとリカバリにリダイレクトされ、そこで保護ポリシーやスケジュールを変更できます。
