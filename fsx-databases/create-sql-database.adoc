= NetApp Workload Factory for Databases で Microsoft SQL データベースを作成する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
新しいMicrosoft SQLデータベースを作成すると、NetApp Workload Factory for Databases内でリソースを管理できるようになります。

.タスク概要
データベース作成時に、データベースのデータ ファイルとログ ファイルを格納する独立したLUNで構成されるFSx for ONTAPファイル システム内に、2つの新しいボリュームが作成されます。新しいデータベース内のデータベース ファイルはシンプロビジョニングされており、新しいデータベースに割り当てられた合計サイズのうち数MBしか消費しません。

データベースのストレージを分離したい場合は、_仮想マウントポイント_を使用することで実現できます。仮想マウントポイントを使用すると、データベースをホスト上のいくつかの共通ドライブに統合できます。

workload factoryでデータベースを作成するには、_表示、計画、および分析_の権限が必要です。あるいは、部分的に完成したコードテンプレートをコピーまたはダウンロードして、workload factoryの外部で操作を完了することもできます。使用するモードを決定するには、link:../fsx-storage/permissions-reference-fsx.html["Workload Factoryの権限について学ぶ"^] を参照してください。


NOTE: SMBプロトコルを使用するMicrosoft SQL Serverは、データベースの作成をサポートしていません。

.開始する前に
新しいデータベースを作成する前に、以下の前提条件をすべて満たしてください。

* *認証情報と権限*：Workload Factoryで新しいデータベースを作成するには、link:../fsx-storage/add-credentials.html["AWSアカウントの認証情報と_操作および修復_権限"^]が必要です。
+
または、Codeboxを使用してテンプレートをコピーし、REST APIを使用してワークロードファクトリの外部にデータベースをデプロイすることもできます。link:../admin/codebox-automation.html["Codeboxによる自動化について詳しくはこちらをご覧ください"^]。

* *Windowsホスト*：_Quick create_ モードを使用する場合、新しいデータベース用に新しいドライブを作成するために、Microsoft SQL Server上で十分な数のドライブレターが利用可能である必要があります。
* *Microsoft SQL Server*：新しいデータベースをホストするには、データベース向けワークロードファクトリに管理対象のMicrosoft SQL Serverが必要です。
* *AWS Systems Manager*：AWS Systems Managerを介してMicrosoft SQLホストで `NT Authority\SYSTEM`ユーザ権限が有効になっていることを確認します。




[[create-a-database]]
== データベースを作成する

Workload Factory では、このタスクを完了するために、「クイック作成」または「詳細作成」のデプロイメント モードを使用できます。

[role="tabbed-block"]
====
.クイック作成
--
.手順
. link:https://console.netapp.com["NetApp Console"^]にログインします。
. メニュー image:workloads-menu-icon.png["ハンバーガーメニューアイコンは、Workload Factoryのメニュー項目であるWorkloadsに移動するために使用します"] から、*ワークロード* > *データベース* を選択します。
. データベースメニューから、*インベントリ*を選択します。
. インベントリで、データベースエンジンタイプとして *Microsoft SQL Server* を選択します。
. データベースを作成する先の、マネージドSQL serverインスタンスを備えたデータベース サーバを選択します。
. 管理対象インスタンスのアクションメニューをクリックし、*ユーザーデータベースの作成*を選択します。
. 「ユーザーデータベースの作成」ページで、「データベース情報」の下に、以下の情報を入力してください：
+
.. *データベース名*：データベースの名前を入力してください。
.. *照合順序*：データベースの照合順序を選択してください。Microsoft SQL Serverのデフォルトの照合順序「SQL_Latin1_General_CP1_CI_AS」が選択されています。


. ファイル設定で、以下の情報を入力してください：
+
.. *ファイル設定モード*：*クイック作成*を選択します。
.. *ファイル名とパス*：
+
*** *データ ファイル名*：データ ファイル名を入力してください。
*** *ログファイル名*：ログファイル名を入力してください。


.. *ファイルサイズ*：データベースのデータサイズとログサイズを入力してください。


. *作成*をクリックします。
+
または、これらのデフォルト設定を今すぐ変更する場合は、*ファイル設定モード*を*詳細作成*に変更してください。



--
.高度な作成
--
.手順
. link:https://console.netapp.com["NetApp Console"^]にログインします。
. メニュー image:workloads-menu-icon.png["ハンバーガーメニューアイコンは、Workload Factoryのメニュー項目であるWorkloadsに移動するために使用します"] から、*ワークロード* > *データベース* を選択します。
. データベースメニューから、*インベントリ*を選択します。
. インベントリで、データベースエンジンタイプとして *Microsoft SQL Server* を選択します。
. データベースを作成する先の、マネージドSQL serverインスタンスを備えたデータベース サーバを選択します。
. 管理対象インスタンスのアクションメニューをクリックし、*ユーザーデータベースの作成*を選択します。
. *ユーザーデータベースの作成*を選択します。
. 「ユーザーデータベースの作成」ページで、「データベース情報」の下に、以下の情報を入力してください：
+
.. *データベース名*：データベースの名前を入力してください。
.. *照合順序*：データベースの照合順序を選択してください。Microsoft SQL Serverのデフォルトの照合順序「SQL_Latin1_General_CP1_CI_AS」が選択されています。


. ファイル設定で、以下の情報を入力してください：
+
.. *ファイル設定モード*：*詳細作成*を選択します。
.. *ファイル名とパス*：
+
... *データ ファイル*：ドライブ文字を選択して、データ ファイル名を入力してください。
+
必要に応じて、*仮想マウントポイント*のボックスをクリックします。

... *ログファイル*：ドライブ文字を選択し、ログファイル名を入力してください。
+
必要に応じて、*仮想マウントポイント*のボックスをクリックします。



.. *ファイルサイズ*：データベースのデータサイズとログサイズを入力してください。


. *作成*をクリックします。


--
====
データベースホストを作成した場合は、「ジョブ監視」タブでジョブの進行状況を確認できます。
