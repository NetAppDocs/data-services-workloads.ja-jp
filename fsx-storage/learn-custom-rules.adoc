= NetApp Console のカスタムルールについて
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
カスタムルールを使用すると、優れた設計のダッシュボードで、NetAppのベストプラクティスとともに、独自のアーキテクチャ標準を設定、チェック、適用できます。



[[overview]]
== 概要

ルールビルダーを使用すると、平易な言葉でカスタムルールを作成できます。これらのルールは、すべてのリソースに対してチェックされます。カスタムルールを使用すると、デフォルトのルールではカバーされない可能性のある、組織の基準、リスク制限、および運用要件を適用できます。


NOTE: アカウント管理者がAI機能を無効にしている場合、新しいルールを作成したり、既存のルールを編集したりすることはできません。既にスケジュールされているルールは、引き続き実行されます。link:../admin/manage-genai-features.html.["AI機能の管理について"^]。



[[how-custom-rules-work]]
== カスタムルールの仕組み

カスタムルールはAIを活用して、平易な言葉で書かれた指示を明確で構造化されたルールに変換します。AIはリクエストを解釈してルールを提案し、指示をどのように理解したかを説明したうえで、ルールの保存またはスケジュールの前に承認を求めます。このプロセスは、以下のことを確実にします：

* ルールは明確に定義され、エラーがないかチェックされています
* カスタムコードは実行されません
* ルールを承認する前に、評価される内容を正確に確認できます
* 各カスタムルールには、評価対象のリソースタイプ、条件ロジック、重要度、評価スケジュール、および是正措置に関するガイダンスが含まれます。




[[before-you-begin]]
== 開始する前に

カスタムルールを作成して実行する前に、以下のものを用意してください：

AWS クレデンシャル:: AWS環境への読み取り専用アクセス。カスタムルールでは、セキュリティ境界として読み取り専用権限が必要です。link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["Workload FactoryにAWS認証情報を追加する"^]。
ONTAP クレデンシャル:: 読み取り専用権限を持つFSxビューアユーザー。Workload Factoryは、まだ存在しない場合、各FSx for ONTAPファイルシステムに読み取り専用ユーザーを作成し、評価を実行できるようにします。
リンクまたはエージェント:: AWS APIがアクセスできない設定を確認するためにONTAPに直接接続する必要があるルールにのみ必要です。link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["リンクを使用してFSx for ONTAPファイルシステムに接続する"^]。




[[limitations]]
== 制限事項

* ルールは問題を自動的に解決するものではありません。提供されたガイダンスに従って、準拠していないリソースをお客様ご自身で修正する必要があります。
* 各ルールは1種類のリソースのみをチェックしますが、幅広いリソースに適用できます。たとえば、1つのルールで複数のリージョン、すべてのリージョン、または複数のアカウントのボリュームを評価できます。異なるリソースタイプを評価するには、それぞれ別のルールを作成します。
* 過剰なスキャンを防ぐため、ルールは1時間に最大1回実行されます。
* ルールは環境を読み取ることしかできず、変更を加えることはできません。
* これらの設定は、後でルールカタログから更新できます。




[[rule-lifecycle]]
== ルールライフサイクル

カスタムルールは、以下の状態を経て進行します。

実行中:: ルールの作成または確認。
作成に失敗しました:: ルールを作成できませんでした。ルールを再度開いて、チャットで編集を続けることができます。
ドラフト:: 保存済みですが、まだスケジュール設定されていません。
検証済みドラフト:: 検証に合格しました。保存またはスケジュール設定が可能です。
編集:: 既存のルールのドラフトコピーを更新します。変更を保存するまで、現在スケジュールされているルールは引き続き実行されます。
スケジュール済み:: アクティブであり、定義されたスケジュールに従って実行されます。
Disabled:: 一時停止中ですが、削除はされていません。再度有効化できます。
削除済み:: 完全に削除されました。




[[custom-rule-examples]]
== カスタムルールの例

本番ボリュームの保護:: 「タグ『Prod』が付いているすべてのボリュームには、スナップショットポリシーがインストールされている必要があります」
+
--
このルールは、会社の要件に従って本番環境のボリュームを保護するためのスナップショットを自動的に作成します。

--
アーカイブボリュームの階層化:: 「『Archive』タグが付いたすべてのボリュームには、階層化ポリシーを『All』に設定する必要があります」
+
--
このルールは、アーカイブされたデータをより安価なストレージに自動的に移動することで、コストを削減します。

--
ファイルシステムの命名規則:: 「すべてのファイルシステムは、命名規則 'fsx-{environment}-{application}' に従う必要があります」
+
--
このルールは、ファイルシステムが組織の命名規則に準拠していることを検証し、管理とコスト配分を容易にします。

--
