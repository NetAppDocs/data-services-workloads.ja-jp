= NetApp Workload Factoryにおけるデータ保護の種類
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
FSx for ONTAPは、データ保護のためのスナップショット、AIを活用したNetApp自律型ランサムウェア対策、レプリケーション、およびバックアップをサポートしています。データを保護するためには、複数のデータ保護方法を組み合わせることをお勧めします。



[[types-of-data-protection]]
== データ保護の種類

ワークロードのデータ保護は、あらゆるデータ損失からいつでも復旧できるようにするのに役立ちます。使用する機能を選択する前に、データ保護の種類について理解しておきましょう。

.Snapshot 数
スナップショットは、ソースボリューム内のボリュームの読み取り専用のポイントインタイムイメージをスナップショットコピーとして作成します。スナップショットコピーを使用すると、個々のファイルを復元したり、ボリュームの内容全体を復元したりできます。スナップショットは、あらゆるバックアップ方法の基礎となるものです。ボリューム上に作成されるスナップショットコピーは、複製されたボリュームとバックアップファイルを、ソースボリュームに加えられた変更と同期させるために使用されます。

.NetApp AIによる自律型ランサムウェア対策
NetApp AIによる自律型ランサムウェア対策（ARP/AI）は、NAS（NFS/SMB）環境におけるワークロード分析を利用して、ランサムウェア攻撃の可能性のある異常なアクティビティを検知し、警告を発します。攻撃が疑われる場合、ARP/AIは、スケジュールされたスナップショットによって提供される既存の保護に加えて、新しい不変のスナップショットを作成します。

.レプリケーション
レプリケーションは、別のFSx for ONTAPファイルシステム上にデータのセカンダリコピーを作成し、セカンダリデータを継続的に更新します。お客様のデータは常に最新の状態に保たれ、災害復旧など、必要な時にいつでも利用可能です。

別のFSx for ONTAPファイルシステムにレプリケートされたボリュームと、クラウドにバックアップファイルの両方を作成することも、レプリケートされたボリュームのみ、またはバックアップファイルのみを作成することもできます。

.バックアップ
データの保護と長期保存のために、クラウドにデータのバックアップを作成できます。必要に応じて、バックアップからボリューム、フォルダ、または個々のファイルを、同じまたは別の作業用ファイルシステムに復元できます。

[[best-practices-for-protecting-your-workload-data]]
== ワークロードデータを保護するためのベストプラクティス

FSx for ONTAPには複数のデータ保護オプションが用意されており、それらを組み合わせて、選択した復旧時点と復旧時間の目標を達成できます。最大限の保護を実現するには、ボリュームスナップショットとボリュームバックアップの両方を使用することをお勧めします。

リカバリポイント目標（RPO）とは、データの最新コピーがどの程度最新の状態であることが保証されるかを示すもので、コピーが作成される頻度によって決まります。復旧時間目標（RTO）とは、データの復旧にかかる時間を定義するものです。



[[protect-your-workload-data-with-snapshots]]
== スナップショットを使用してワークロードデータを保護します

スナップショットは、定期的に取得されるボリュームの仮想的なポイントインタイムバージョンです。標準のファイルシステムコマンドを使用してスナップショットにアクセスできます。スナップショットは、最短1時間のRPOを提供します。RTOはリストアするデータ量に依存し、主にボリュームのスループット制限によって制限されます。また、スナップショットを使用すると、特定のファイルやディレクトリをリストアできるため、RTOをさらに短縮できます。スナップショットは、ボリュームに加えられた変更に対してのみ追加のボリュームスペースを消費します。



[[protect-your-workload-data-with-netapp-autonomous-ransomware-protection-with-ai]]
== AIを搭載したNetApp自律型ランサムウェア対策でワークロードデータを保護

NetAppAI搭載自律型ランサムウェア対策（ARP/AI）は、ウイルス対策ソフトウェアが侵入を検知できなかった場合に、重要な追加防御層として機能します。ARP/AIポリシーを設定すると、すべてのストレージVMと、既存および新規に作成されたすべてのボリュームに対して有効になります。有効化すると、ARP/AIはすべてのボリュームとストレージVMを検出し、保護します。ファイル拡張子が異常と判定された場合は、アラートの内容を評価する必要があります。



[[protect-your-workload-data-with-volume-replication]]
== ボリュームレプリケーションでワークロードデータを保護

ボリュームレプリケーションは、ボリュームの最新データ（すべてのスナップショットを含む）のコピーを別のリージョンに作成します。ボリュームバックアップからのボリューム全体のリストア処理で数時間のRTOを許容できない場合は、ボリュームレプリケーションの実行を検討してください。ボリュームレプリケーションによって、最新のデータが別のリージョンで利用可能になることは保証されますが、クライアント側で別のリージョンのボリュームを使用するように設定を調整する必要があります。



[[protect-your-workload-data-with-backups]]
== バックアップを使用してワークロードデータを保護します

ボリュームバックアップは、ボリュームの独立したポイントインタイムコピーを提供します。これらは、古いバックアップを保存し、データの必要なセカンドコピーを提供するために使用できます。日次、週次、月次のバックアップスケジュールにより、最短1日からのRPOを設定できます。ボリュームバックアップは、全体でのみ復元できます。バックアップからのボリューム作成（RTO）には、バックアップのサイズに応じて数時間から数日かかる場合があります。



[[recommendations-for-protecting-your-workload-data]]
== ワークロードデータを保護するための推奨事項

ワークロードデータの保護に関して、以下の推奨事項を検討してください。

* ボリュームレプリケーションを災害復旧に活用する：アプリケーションで低いRTOが求められる場合は、ボリュームレプリケーションを使用してデータを別のリージョンに複製することを検討してください。
* ボリュームバックアップとスナップショットを併用してください：この2つの機能を併用することで、スナップショットからファイルを復元できるだけでなく、ボリュームが失われた場合でもバックアップから完全な復元を実行できます。
* ボリュームのバックアップ ポリシーを定義する：バックアップ ポリシーが、バックアップの保存期間と頻度に関する会社の要件を満たしていることを確認してください。各ボリュームにつき、最低でも2つのデイリーバックアップを保持することをお勧めします。
* スナップショットのスケジュールを定義する：古いスナップショットは、データの復元に使用される可能性が低くなります。古いスナップショットを保持することによるメリットの逓減と、追加のスナップショット容量にかかるコストを考慮したスナップショットスケジュールを定義することをお勧めします。
* ランサムウェア攻撃に対する保護層を追加するには、ファイルシステムまたは個々のボリュームに対してARP/AIポリシーを有効にしてください。
